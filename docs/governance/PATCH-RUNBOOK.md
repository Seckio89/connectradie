# Patch runbook — how every future bug gets fixed

This is the "program" that automates patches. It is a process, not software:
the automation is the existing checker scripts plus this fixed sequence. Any
agent (or developer) handed a bug follows it verbatim.

## The sequence

1. **Reproduce & classify.** Confirm the bug, then classify it against
   [CHANGE-POLICY.md](CHANGE-POLICY.md). Unsure = Tier B.
2. **Tier B?** Write an entry in [DECISIONS-PENDING.md](DECISIONS-PENDING.md)
   using its template (what/why/pros/cons/risk/effort/recommendation). Stop.
   No code until the owner approves.
3. **Tier A:** branch `fix/<short-slug>` off `master`.
4. Fix it minimally, following existing patterns. No drive-by refactors.
5. **Verify by execution** (never by re-reading):
   - `npm run typecheck` — always
   - `npm run check:columns` — if any query changed
   - the class checker from the table below
   - visual bugs: screenshot before/after at 1280×800 **and** 375×812
     (dark theme; check the *effective* background, not the element alone)
6. Open a PR: what/why, screenshots, checks run, and the line
   "Tier A per CHANGE-POLICY.md".
7. CI runs the full gate. **The owner merges** when green — merge = deploy.

## Which checker verifies which bug class

| Bug class | Command | What it proves |
|---|---|---|
| Type errors, broken imports | `npm run typecheck` | frontend compiles (never `npx tsc --noEmit` — it checks nothing) |
| Edge-function code | `npm run typecheck:edge` | Deno type-check ratchet |
| Wrong/missing DB column in a query | `npm run check:columns` | every column in `.select()/.insert()/.update()` exists (TS cannot catch this) |
| Dead link, orphan route, missing title, redirect eating a query string | `npm run check:nav` | route graph is navigable (baseline `.nav-baseline.json`) |
| Unreadable text (static classes) | `npm run check:ink` + `npm run check:tokens` | no `text-ct-ink` on unreadable fills; every `ct-` utility resolves |
| Unreadable text (rendered) | `npm run build` then `npm run check:contrast` | WCAG AA in a real browser, desktop + iPhone 13 |
| Schema/migration drift | `npm run check:drift` | migrations still rebuild prod |
| Deployed edge fn ≠ repo | `npm run check:edge-drift` | deployed code matches the repo |
| Edge-fn list docs stale | `npm run check:edge-docs` (`:fix` to write) | documented list matches disk |
| Money-path behaviour | `npm run e2e:doctor` then the relevant `e2e:*` harness | real flow against the test project (never prod) |
| Logic/unit regressions | `npm run test:run` (add `--no-file-parallelism` if flaky) | vitest suite |
| Whole-app navigability (personas) | `npm run audit:nav` | client/tradie/admin crawl vs the e2e test project |

## Batching rule

Group same-class fixes into one branch (e.g. `fix/audit-copy-batch-1`), small
enough that the owner can judge the PR from its screenshots in under a minute.
Never mix classes that need different reviewers' eyes (copy vs layout vs
links) unless the batch is tiny.

## Standing traps (read before fixing anything)

- `src/styles/mobile-responsive.css` is imported globally and latches onto
  generic utility combinations — grep it for your selectors and re-check at
  375px before calling any UI fix done.
- Browser-tab titles come from `PAGE_TITLES` / `DYNAMIC_TITLES` in
  `src/App.tsx`, **not** from the `<SEO>` component (react-helmet is not
  taking effect).
- `.claude/skills/*.md` are regenerated by `setup-skills.sh` — never encode
  policy there; it lives in `docs/governance/`.
- Never edit an existing migration; never commit `.env`; Vercel previews
  cannot call edge functions (CORS) — test those on `localhost:5173`.
- New route? Bump the service-worker `CACHE_NAME` and expect the nav ratchet
  to move.

## Reporting

The fix PR is the report. If a Tier A fix uncovers a Tier B issue while in
the code, do **not** widen the fix — file it in DECISIONS-PENDING.md and
finish the original patch.
